PENJELASAN KODINGAN: MkbdAllDataFullService.java
=================================================

Gw bedah baris per baris. File ini cuma ~60 baris,
isinya 1 method doang (getAllData).


-----------------------------------------------------------
BAGIAN 1: IMPORT & ANOTASI KELAS (baris 1-17)
-----------------------------------------------------------

  package com.ciptadana.mkbd_master_menu.service.MkbdAllData;

Lokasi file ini di package mana. Wajib ada di Java.

  import com.ciptadana.mkbd_master_menu.config.CacheConfig;
  import lombok.RequiredArgsConstructor;
  import lombok.extern.slf4j.Slf4j;
  import org.springframework.cache.annotation.Cacheable;
  import org.springframework.stereotype.Service;
  import java.util.LinkedHashMap;
  import java.util.List;
  import java.util.Map;
  import java.util.concurrent.CompletableFuture;

Daftar barang yg dipake. Tiap class dari luar wajib di-import.

  @Slf4j

Anotasi Lombok. Otomatis bikin variable bernama 'log' di kelas
ini, jadi lu bisa langsung pake log.info(...), log.error(...)
tanpa nulis: private static final Logger log = ...

  @Service

Nandain ke Spring: "kelas ini service, tolong bikinin instance-
nya, masukin ke container DI". Tanpa ini, Spring gak akan
ngenalin kelas ini.

  @RequiredArgsConstructor

Anotasi Lombok. Otomatis bikin constructor yg nerima semua
field 'final'. Di kelas ini ada 2 field final (registry &
scriptExecutor), jadi Lombok bikin:
    public MkbdAllDataFullService(SqlScriptRegistry registry,
                                  SqlScriptExecutor exec) {
        this.registry = registry;
        this.scriptExecutor = exec;
    }
Spring otomatis nyuntikin (inject) 2 dependency itu.

BAGIAN 2: FIELD (baris 19-20)
-----------------------------------------------------------

  private final SqlScriptRegistry registry;
  private final SqlScriptExecutor scriptExecutor;

2 dependency yang dipakai:
  - registry      : tempat ambil 98 SqlScript
  - scriptExecutor: tempat eksekusi SQL

'final' = sekali di-set (di constructor), gak bisa diubah lagi.
Kombinasi 'private final' + Lombok @RequiredArgsConstructor =
constructor injection (cara DI yg direkomendasikan Spring).

BAGIAN 3: ANOTASI METHOD (baris 22)
-----------------------------------------------------------

  @Cacheable(value = CacheConfig.MKBD_ALL_DATA_FULL_CACHE,
             key = "#genDate")

Spring bakal "bungkus" method ini dengan logic cache:
  - value : nama cache-nya (ada di CacheConfig)
  - key   : pake parameter genDate sbg kunci cache

Cara kerjanya:
  1. Sebelum method dijalanin, Spring cek: "udah ada hasil
     buat genDate ini di cache?"
  2. Kalo ADA -> langsung balikin hasil cache, method GAK
     dijalanin sama sekali.
  3. Kalo GAK ADA -> jalanin method, simpen hasilnya di
     cache pake key genDate, baru balikin.

Jadi @Cacheable ini "ajaib" - body method-nya gak nyebut
cache sama sekali, tapi Spring yg handle di belakang layar.

BAGIAN 7: JALANIN SEMUA QUERY PARALEL (baris 29-33)
-----------------------------------------------------------

  Map<String, CompletableFuture<List<Map<String, Object>>>>
                                            futures =
      new LinkedHashMap<>();

Bikin Map kosong. Tipenya panjang, tapi intinya:
  key   = String (nama identifier query, contoh "detail:vd51/baris30")
  value = CompletableFuture<List<Map<String,Object>>>
        = "janji" yang nanti berisi hasil query (list of row)

LinkedHashMap (bukan HashMap biasa) = inget urutan masukin.

  for (SqlScript s : scripts) {
      futures.put(s.key(), scriptExecutor.runAsync(s, genDate));
  }

Loop semua SqlScript. Tiap iterasi:
  - Panggil scriptExecutor.runAsync(s, genDate)
       -> ini LANGSUNG return "janji", GAK NUNGGU query selesai.
       -> Query mulai jalan di background (di thread pool).
  - Simpen "janji" itu ke Map dengan key dari script.

Setelah loop selesai, semua 98 query udah mulai jalan paralel
(walaupun pool-nya 6, jadi yg bener-bener jalan barengan max 6,
sisanya antri).

  CompletableFuture.allOf(
      futures.values().toArray(CompletableFuture[]::new))
      .join();

Translate: "Tunggu sampai SEMUA janji selesai".
  - allOf(...)  : gabungin semua future jadi 1 future besar.
  - .join()     : tahan thread sini sampai future besar selesai.

Setelah baris ini eksekusi, dijamin semua 98 query udah selesai
(atau gagal). Kalau ada yg gagal, exception-nya dilempar di sini.

BAGIAN 8: SUSUN HASIL JADI STRUKTUR NESTED (baris 35-50)
-----------------------------------------------------------

  Map<String, Object> detail = new LinkedHashMap<>();
  Map<String, Object> summary = new LinkedHashMap<>();

Bikin 2 Map kosong sbg "kantong" (bucket) buat ngumpulin hasil:
  - detail : utk script yg type-nya "detail"
  - summary: utk script yg type-nya "summary"

  for (SqlScript s : scripts) {

Loop semua script lagi (kali ini buat susun hasil).

      List<Map<String, Object>> rows =
          futures.get(s.key()).join();

Ambil hasil query dari Map futures. Karena udah dijamin selesai
di Bagian 7, .join() di sini langsung kasih hasil tanpa nunggu.

      Map<String, Object> bucket =
          "detail".equals(s.type()) ? detail : summary;

Pilih kantong: kalo type-nya "detail" pake bucket detail,
kalo bukan ("summary") pake bucket summary.

Catatan: nulis "detail".equals(s.type()) bukan s.type().equals
("detail") buat nge-hindarin NullPointerException kalo s.type()
null.

      if (s.baris() == null) {
          bucket.put(s.vd(), rows);
      } else {

Cek: script ini punya "baris" gak?
  - Kalo NULL artinya script ini tinggal di level vd doang
    (contoh: detail/coa.sql -> vd="coa", baris=null).
    Langsung simpen di bucket pake key vd.

      } else {
          @SuppressWarnings("unchecked")
          Map<String, Object> vdMap =
              (Map<String, Object>) bucket.computeIfAbsent(
                  s.vd(), k -> new LinkedHashMap<>());
          vdMap.put(s.baris(), rows);
      }

  - Kalo PUNYA baris (contoh: detail/vd51/baris30.sql):
    Strukturnya harus nested -> bucket["vd51"]["baris30"] = rows

    computeIfAbsent(s.vd(), k -> new LinkedHashMap<>()):
      "Cek apakah key 'vd51' udah ada di bucket?
       Kalo BELUM, bikin LinkedHashMap kosong, masukin, balikin.
       Kalo UDAH, balikin yg udah ada."
    Praktis buat hindarin null-check manual.

    @SuppressWarnings("unchecked"):
      Compiler ngeluh karena cast (Map<String,Object>) gak
      type-safe (Map yg dibalikin computeIfAbsent tipenya
      Object). Anotasi ini bilang ke compiler "iya gw tau,
      diem aja".

    vdMap.put(s.baris(), rows):
      Setelah dpt vdMap-nya, simpen rows pake key baris.

-----------------------------------------------------------
RANGKUMAN: KENAPA KODINGNYA SINGKAT TAPI POWERFUL?
-----------------------------------------------------------

Method ini cuma ~35 baris efektif tapi handle 98 query paralel
+ caching + nested response. Tricks-nya:

  1. @Cacheable : caching otomatis tanpa nulis logic cache
  2. Lombok @Slf4j & @RequiredArgsConstructor : skip
     boilerplate logger & constructor
  3. CompletableFuture.allOf().join() : tunggu banyak future
     dengan 1 baris
  4. computeIfAbsent : handle "bikin kalo belum ada" tanpa
     if-else
  5. LinkedHashMap : urutan key di JSON terjaga
  6. Map<String,Object> nested : fleksibel buat data dinamis
     tanpa bikin 98 POJO

Kalo semua di atas ditulis manual, file ini bisa 200+ baris.
